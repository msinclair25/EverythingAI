# AI Accessibility

Accessibility is a product, data, evaluation, procurement, and operations responsibility—not a final interface check.

## Design across disability and context

Support keyboard and assistive technology, semantic structure, text alternatives, captions/transcripts, visual contrast, resizable text, non-color cues, controllable timing, reduced motion, clear language, error identification, multiple input/output modes, and human/accessible alternatives.

AI adds risks: speech recognition variance, image-description errors, inaccessible CAPTCHAs, automated video/avatar issues, cognitive burden from uncertain conversation, model assumptions about communication, and screening tools that disadvantage disabled applicants.

## Evaluation

Use automated checks for detectable issues, expert review, and task-based research with people using relevant assistive technologies. Test model behavior and workflow—not only page markup. Provide accommodation, appeal, and support processes.

For U.S. employment uses, EEOC guidance highlights ADA risks from algorithmic tools and the need for reasonable-accommodation processes. Consult current counsel/policy for a specific use.

## Quiz

1. Why are automated accessibility scans insufficient? 2. Name two AI-specific accessibility risks. 3. What is an equivalent path? 4. Why test the workflow rather than only UI markup?

> [!success]- Answers
> 1. They cannot assess all usability, assistive-tech, cognitive, content, or model-behavior issues. 2. Speech variance, image-description errors, inaccessible generated content, screening bias, or cognitive overload. 3. An accessible way to achieve the same purpose without inferior consequence. 4. Model outputs, time limits, handoffs, and accommodations can fail even with valid markup.

## Flashcards

Equivalent path:: An accessible route to the same purpose and outcome.

Reasonable accommodation process:: A way to request and receive appropriate adjustments under applicable obligations.

Accessibility evaluation:: Automated, expert, and disabled-user testing of interface, content, model behavior, and workflow.
