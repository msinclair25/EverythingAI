# Project Selection Guide

Suggested projects are evidence prompts, not step-by-step labs.

## Choose for signal

Score each idea 0–2:

| Dimension | 0 | 1 | 2 |
|---|---|---|---|
| Role relevance | cosmetic | adjacent | mirrors core role decision |
| Evidence | only demo | some metrics | versioned representative evaluation |
| Tradeoffs | hidden | described | tested and justified |
| Failure work | none | examples | taxonomy, severity, mitigation, residual limits |
| Ownership | copied | modified tutorial | independently framed and defended |
| Communication | screenshot | README | role-appropriate artifacts for multiple audiences |
| Feasibility | unclear | substantial dependency | achievable safely with allowed data/tools |

Prefer ideas scoring 11+ of 14.

## Portfolio set

1. **Small foundation project:** one clear concept, 4–12 hours.
2. **Substantial role project:** end-to-end decisions, 25–80 hours.
3. **Differentiating edge:** another role/domain, 10–30 hours.

One deep project beats five nearly identical chatbots.

## Minimum artifact pack

- audience/problem and baseline;
- scope and non-goals;
- data/source rights and provenance;
- architecture/workflow or process map;
- alternatives and decision record;
- representative evaluation design/results;
- errors, limitations, security/privacy/safety/accessibility considerations;
- cost/operations or adoption plan as relevant;
- demo or sample artifact;
- next decision.

## Safe data

Use public data under suitable terms, generated scenarios clearly labeled synthetic, or data you are authorized to use. Remove secrets and personal data. Do not upload employer/customer documents. Document licenses and limitations. Synthetic data can reproduce sensitive patterns and needs validation.

## Explain the project

Use: problem → constraint → alternatives → choice → evidence → failure → tradeoff → result → next step. State what you did and what was borrowed. Never disguise hand edits, vendor features, or model-generated code.
